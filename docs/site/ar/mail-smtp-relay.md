# بريد المنتج عبر Google Workspace (مرحّل SMTP)

> للمسؤولين والمشغّلين. أكمل دليل DNS أولًا: لا يُسلِّم المرحّل جيدًا إلا إذا نجحت SPF وDKIM وDMARC.

يرسل Curahold روابط تسجيل الدخول والتذكيرات وإشعارات التجربة والملخصات. صندوق Gmail العادي غير مخصّص لبريد التطبيقات؛ أما **خدمة مرحّل SMTP** من Google فمخصّصة لذلك، وتبقى داخل Google Workspace دون خدمة بريد أخرى.

## 1. فعّل المرحّل

وحدة تحكم المشرف ← التطبيقات ← Google Workspace ← Gmail ← **التوجيه** ← **خدمة مرحّل SMTP** ← تهيئة:

- **المرسلون المسموح لهم:** العناوين في نطاقاتي فقط.
- **المصادقة:** حدّد **طلب مصادقة SMTP** (تعمل الخدمة المستضافة على خوادم بلا عنوان ثابت، فتسجّل الدخول بدل إدراجها في قائمة السماح). في الاستضافة الذاتية بعنوان ثابت يمكن استخدام «قبول البريد من عناوين IP المحددة فقط».
- **التشفير:** حدّد **طلب تشفير TLS**.
- احفظ. قد يستغرق التفعيل ساعة.

## 2. حساب الإرسال

اختر المستخدم الذي سيسجّل الدخول إلى المرحّل (حساب المالك يكفي) مع تفعيل التحقق بخطوتين، وأنشئ له **كلمة مرور للتطبيق**. أضف `no-reply@` اسمًا مستعارًا له.

## 3. إعداد Curahold

**المستضافة (Cloudflare Workers)** — كأسرار (`wrangler secret put …`):

| الإعداد | القيمة |
| --- | --- |
| `SMTP_RELAY_USER` | مستخدم الخطوة 2، مثل `owner@example.com` |
| `SMTP_RELAY_PASSWORD` | كلمة مرور التطبيق الخاصة به |
| `EMAIL_FROM` | `Curahold <no-reply@example.com>` |
| `EMAIL_PROVIDER` | `google_relay` (يُختار تلقائيًا عند ضبط الإعدادين السابقين) |
| `SMTP_RELAY_HOST`, `SMTP_RELAY_PORT` | فقط لتغيير القيم الافتراضية `smtp-relay.gmail.com` و`587` |

مسار الشيفرة: `api/src/lib/smtpRelay.ts` ‏(STARTTLS على المنفذ 587؛ المنفذ 25 مغلق في Workers).

**الاستضافة الذاتية** — في ملف `.env`:

```
SMTP_URL=smtp://owner%40example.com:APP-PASSWORD@smtp-relay.gmail.com:587
EMAIL_FROM=Curahold <no-reply@example.com>
```

ثم أعد تشغيل التطبيق.

## 4. التحقق

سجّل الخروج واطلب رابط تسجيل دخول. يجب أن تصل الرسالة من `no-reply@…` وأن تُظهر SPF وDKIM وDMARC بحالة **PASS**. إن لم يصل شيء، يذكر سجل التطبيق خطوة SMTP التي فشلت.

## 5. الحدود — ومتى تلزم خدمة إرسال مخصّصة

يقبل المرحّل حتى **10,000 مستلم يوميًا لكل مستخدم** (الحد المنشور من Google؛ تحقّق منه). يلزم نقل بريد المنتج إلى خدمة إرسال مخصّصة — وهو قرار المالك ومدفوع — عند حدوث **أيٍّ** مما يلي:

- تجاوز بريد المنتج اليومي بانتظام **نصف الحد** (5,000 مستلم يوميًا)؛
- تراجع التسليم: ارتداد أعلى من **2%**، أو شكاوى قرب **0.1%**، أو وصول الرسائل إلى البريد العشوائي؛
- الحاجة إلى أحداث تسليم لكل رسالة (webhooks) أو سمعة إرسال منفصلة لأنواع البريد؛
- التخطيط لـ**حملات تسويقية** — لا تُرسل عبر المرحّل أبدًا.

التحويل مجرد إعداد: للخدمة المستضافة مشغّل جاهز (`EMAIL_PROVIDER=resend` مع `RESEND_API_KEY`). أضفه إلى صفحة المعالجين الفرعيين وأبلغ المسؤولين قبل 30 يومًا.

## 6. عندما لا يخرج البريد {#failures}

يُعاد الرفض المؤقت (`421` أو `450` أو `451` أو انقطاع الاتصال) مرة واحدة عبر اتصال جديد. أما الرفض الدائم فلا يُعاد: `535` (تغيّرت كلمة مرور التطبيق أو أُلغيت: أنشئ واحدة جديدة واستبدل `SMTP_RELAY_PASSWORD`)، و`550 5.4.5` (الحد اليومي)، و`550 5.1.1` (عنوان غير موجود). يرى الناس حينها «تعذّر إرسال البريد الإلكتروني الآن. يرجى المحاولة بعد بضع دقائق، وإن تكرّر ذلك فأبلغ المسؤول.» بلغتهم، ولا يرون رد خادم الترحيل أبدًا؛ فهذا يذهب إلى سجل أخطاء التطبيق مع خطوة SMTP.
