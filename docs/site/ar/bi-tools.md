# ربط أداة ذكاء أعمال

في Curahold **موجز تحليلات** واحد للقراءة فقط مخصّص لأدوات ذكاء الأعمال. تقرؤه Power BI وExcel وMicrosoft Fabric وTableau وQlik وZoho Analytics بوصفه **موجز OData**، وتحصل Looker Studio والبرامج النصية والأدوات الأخرى على البيانات نفسها بصيغة **JSON أو CSV**. لا يمكن تغيير أي شيء في Curahold من خلاله.

أسماء القوائم أدناه كما تظهر في الواجهة الإنجليزية لكل أداة؛ اختر ما يقابلها في الواجهة العربية.

## قبل أن تبدأ

1. افتح **الإعدادات ← التحليلات وذكاء الأعمال**. تحتاج إلى صلاحية تصدير البيانات (يملكها المسؤولون والمديرون).
2. اختر **مفتاح تحليلات جديد**. سمّه (مثلًا "لوحة المبيعات في Power BI")، واختر مجموعات البيانات والأقسام التي يُسمح له بقراءتها، وتاريخ انتهائه.
3. انسخ المفتاح الآن: لا يظهر إلا مرة واحدة. يبدأ بـ `chb_`.
4. انسخ العنوان الذي تحتاجه من الصفحة نفسها:
   - موجز OData: `https://your-company.curahold.com/api/analytics/odata/`
   - JSON وCSV: `https://your-company.curahold.com/api/analytics/v1/`

عندما تسألك الأداة عن طريقة تسجيل الدخول اختر **Basic**: اكتب أي شيء في اسم المستخدم، والصق المفتاح في كلمة المرور.

يقرأ المفتاح ما تراه أنت في Curahold بالضبط: العملاء واللوحات والحقول نفسها. الحقل الذي لا يراه دورك لا يظهر حتى كعمود. إذا غادرت الشركة أو فقدت صلاحية التصدير يتوقف المفتاح. **استبدال السرّ** يعطي المفتاح نفسه قيمة جديدة، و**إلغاء** ينهيه فورًا.

## مجموعات البيانات

| مجموعة البيانات | ما فيها |
| --- | --- |
| `Customers` | صف لكل عميل، وكل حقل عميل يحق لك رؤيته في عمود خاص به |
| `Renewals` | العملاء الذين لديهم تاريخ تجديد: القيمة والصحة وفرص التجديد المفتوحة |
| `HealthHistory` | مؤشر صحة كل عميل في كل يوم |
| `Opportunities` | مسار المبيعات: المبلغ والمرحلة والحالة وتاريخ الإغلاق |
| `Tickets` | تذاكر الدعم |
| `Contacts` | جهات الاتصال لدى عملائك |
| `Records…` | مجموعة لكل نوع سجلات أضفته (العقود، المخاطر…) |
| `Boards` و`Tasks` و`TaskAssignees` | اللوحات ومهامها، وصف لكل مهمة ولكل مكلَّف بها |
| `Sprints` و`SprintBurndown` | السبرنتات، والنطاق والعمل المتبقي في كل يوم |
| `People` | الاسم والدور، لإظهار الأسماء بدل معرّفات المالكين والمكلّفين |

في كل مجموعة بيانات عمودا `Id` و`ModifiedAt` (آخر وقت تغيّر فيه الصف). وفي معظمها `IsDeleted` أيضًا: الصفوف المؤرشفة تبقى في الموجز مع `IsDeleted = true` حتى يزيلها التحديث من تقاريرك. اربط المجموعات عبر أعمدة المعرّفات: `Tasks.CustomerId` ← `Customers.Id`، و`Tasks.BoardId` ← `Boards.Id`، و`OwnerId` ← `People.Id`.

## Power BI

1. في Power BI Desktop اختر **Get data → OData feed**.
2. الصق عنوان OData واختر **OK**.
3. اختر **Basic**. اسم المستخدم: أي شيء. كلمة المرور: مفتاح التحليلات. اختر **Connect**.
4. حدّد مجموعات البيانات التي تريدها في Navigator واختر **Load** (أو **Transform data** لحذف أعمدة أولًا).
5. بعد النشر افتح **Settings → Data source credentials** للنموذج الدلالي، واختر **Basic** مع المفتاح مرة أخرى، وفعّل **scheduled refresh**.

إذا طلبت خدمة Power BI بوابة (gateway) لتسجيل الدخول بطريقة Basic، فاستخدم المفتاح بوصفه **Web API key**: في **Transform data → Advanced editor** اكتب المصدر هكذا `OData.Feed("https://your-company.curahold.com/api/analytics/odata/Tasks", null, [ApiKeyName = "key", Implementation = "2.0"])`، ثم اختر **Web API** والصق المفتاح عندما يطلبه Power BI.

**مجموعات البيانات الكبيرة.** للتحديث التدريجي ضع النطاق في العنوان ليصفّي Curahold البيانات قبل إرسالها:

```
let
    Start = DateTime.ToText(RangeStart, "yyyy-MM-ddTHH:mm:ss") & "Z",
    End = DateTime.ToText(RangeEnd, "yyyy-MM-ddTHH:mm:ss") & "Z",
    Source = OData.Feed("https://your-company.curahold.com/api/analytics/odata/Tasks?$filter=CreatedAt ge " & Start & " and CreatedAt lt " & End, null, [Implementation = "2.0"])
in
    Source
```

ثم اضبط سياسة التحديث التدريجي للجدول كالمعتاد، وفعّل **Detect data changes** مع العمود `ModifiedAt` حتى تُقرأ من جديد الفترة التي تغيّرت صفوفها.

## Excel

1. في Excel لنظام Windows اختر **Data → Get Data → From Other Sources → From OData Feed**.
2. الصق عنوان OData واختر **OK**.
3. اختر **Basic**، واكتب أي اسم مستخدم، والصق المفتاح في كلمة المرور، ثم **Connect**.
4. اختر مجموعات البيانات في Navigator ثم **Load**.
5. يجلب **Data → Refresh All** أحدث البيانات متى شئت.

## Microsoft Fabric

1. في مساحة العمل اختر **New item → Dataflow Gen2**، ثم **Get data → OData**.
2. الصق عنوان OData. في بيانات اعتماد الاتصال اختر **Basic**: أي اسم مستخدم، والمفتاح كلمةً للمرور.
3. اختر مجموعات البيانات وعدّلها إن لزم، وأضف **data destination** (مستودع lakehouse أو warehouse).
4. اختر **Publish** ثم حدّد جدول تحديث لتدفق البيانات.

يمكن أيضًا لنشاط **Copy activity** في مسار البيانات قراءة الموجز نفسه بموصل OData وتسجيل دخول Basic.

## Tableau

1. في Tableau Desktop اختر **Connect → To a Server → OData**.
2. في خانة الخادم الصق عنوان مجموعة بيانات واحدة، مثل `https://your-company.curahold.com/api/analytics/odata/Customers`.
3. اختر **Use username and password**: أي اسم مستخدم، والمفتاح كلمةً للمرور. اختر **Sign In**.
4. يقرأ Tableau موجز OData بوصفه **مستخلَصًا (extract)**. أضف اتصال OData آخر لكل مجموعة بيانات تريدها واربطها عبر أعمدة المعرّفات.
5. عند النشر إلى Tableau Cloud أو Server ضمّن بيانات الاعتماد وحدّد جدولًا لتحديث المستخلَص.

## Looker Studio

تحتاج Looker Studio إلى موصل لقراءة موجز كهذا. **موصل Curahold الخاص بـ Looker Studio قادم قريبًا.** وحتى ذلك الحين:

1. في جدول بيانات Google جديد اكتب في الخلية A1: `=IMPORTDATA("https://your-company.curahold.com/api/analytics/v1/Customers.csv?limit=5000&key=مفتاحك")`.
2. في Looker Studio اختر **Create → Data source → Google Sheets** وحدّد ذلك الجدول.
3. أنشئ مفتاحًا لهذا الغرض وحده، مقصورًا على مجموعات البيانات التي يحتاجها الجدول: كل من يستطيع تعديل الجدول يرى المفتاح في الصيغة. ألغِ المفتاح في Curahold إذا اتسعت مشاركة الجدول أكثر من اللازم.

ويمكنك أيضًا إبقاء جدول محدّثًا عبر **أنظمة إدارة العملاء وجداول البيانات** (الإعدادات ← أنظمة إدارة العملاء وجداول البيانات) واستخدامه في Looker Studio.

## Qlik

1. في Qlik Sense أو Qlik Cloud اختر **Add data → OData** (أو **Create new connection → OData**).
2. الصق عنوان OData، واختر المصادقة **Basic**: أي اسم مستخدم، والمفتاح كلمةً للمرور.
3. اختر مجموعات البيانات وحمّلها، وحدّد جدول إعادة التحميل في إعدادات التطبيق.

يعمل موصل REST في Qlik أيضًا مع عنوان JSON ‏(`…/api/analytics/v1/Customers.json`)، بتسجيل دخول Basic وترقيم الصفحات بطريقة "next URL" عبر الحقل `next`.

## Zoho Analytics

1. اختر **Create → New Workspace → Web URL / Feeds** (الاستيراد من موجز ويب).
2. الصق عنوان مجموعة بيانات واحدة: عنوان OData ‏(`…/api/analytics/odata/Customers`) أو عنوان CSV ‏(`…/api/analytics/v1/Customers.csv`).
3. في المصادقة اختر **Basic**: أي اسم مستخدم، والمفتاح كلمةً للمرور.
4. لترقيم الصفحات اختر **next page URL**: ‏`@odata.nextLink` في OData، و`next` في JSON.
5. حدّد عدد مرات تكرار الاستيراد.

## Metabase / Superset

يقرأ Metabase وSuperset قواعد البيانات لا موجزات الويب. سيصبح الاتصال المباشر ممكنًا مع ميزة **التصدير إلى مستودع البيانات** في Curahold (إلى BigQuery أو Snowflake)، وهي قادمة قريبًا. وحتى ذلك الحين ارفع ملف CSV من `…/api/analytics/v1/<مجموعة-البيانات>.csv` إن كان إعدادك يسمح برفع الملفات.

## أدوات أخرى وبرامج نصية

يقبل عنوان JSON وCSV ما يلي:

| الخيار | معناه |
| --- | --- |
| `limit` | عدد الصفوف في الصفحة، حتى 5000 (الافتراضي 1000) |
| `page` أو `offset` | الترقيم برقم الصفحة أو بموضع الصف |
| `cursor` | قيمة `next` من الصفحة السابقة (الأسرع مع المجموعات الكبيرة) |
| `since` | الصفوف التي تغيّرت في هذا التاريخ أو الوقت أو بعده فقط، مثل `2026-11-01` |
| `fields` | هذه الأعمدة فقط، مثل `Id,Name,ModifiedAt` |
| `filter` و`orderby` | التعبيرات نفسها التي يقبلها `$filter` و`$orderby` في OData |
| `count=1` | إرجاع العدد الإجمالي للصفوف أيضًا |

أرسل المفتاح بطريقة Basic (كلمة مرور) أو بالترويسة `Authorization: Bearer chb_…`. صفحة JSON بهذا الشكل `{ "dataset": "Tasks", "rows": [...], "next": "…" }`، وصفحات CSV تعطي العنوان التالي في ترويسة `Link`. وتقرأ أدوات مثل Domo وSAP Analytics Cloud وQuick BI وFineBI عنوان JSON أو OData بالطريقة نفسها.

يفهم موجز OData ‏`$select` و`$filter` ‏(`eq ne gt ge lt le` و`and` و`or` و`not` و`contains` و`startswith` و`endswith`) و`$orderby` و`$top` و`$skip` و`$count` و`/$count`. ولا يقدّم `$expand`: اربط مجموعات البيانات عبر أعمدة المعرّفات بدلًا منه.

## التحديث والحدود

- تصل مجموعات البيانات الكبيرة في صفحات من 1,000 صف، وتتبع أدوات ذكاء الأعمال رابط الصفحة التالية تلقائيًا.
- **التغييرات فقط:** صفِّ على `ModifiedAt` ‏(`$filter=ModifiedAt ge 2026-11-01T00:00:00Z`) أو استخدم `since` في JSON. ومع الترويسة `Prefer: odata.track-changes` تعطي الصفحة الأخيرة أيضًا `@odata.deltaLink` يُرجع لاحقًا ما تغيّر فقط.
- يمكن لكل مفتاح إرسال نحو طلبين في الثانية، ولكل شركة حصة يومية من الصفوف. عند تجاوزها يردّ الموجز بالرمز 429 ويذكر متى يمكن المحاولة مجددًا.
- تُسجَّل كل قراءة (من، وبأي مفتاح، وأي مجموعة بيانات، وكم صفًا) وتظهر في الإعدادات تحت **آخر عمليات القراءة**.

## إذا حدث خطأ

- **401 / الأداة تطلب بيانات الاعتماد مجددًا:** المفتاح خاطئ أو ملغى أو انتهت صلاحيته، أو تُرك اسم المستخدم فارغًا في أداة تشترطه: اكتب فيه أي شيء.
- **403:** لم يعد لصاحب المفتاح صلاحية تصدير البيانات.
- **404 لمجموعة بيانات:** المفتاح مقصور على مجموعات بيانات أو أقسام أخرى، أو حقول تلك المجموعة مغلقة أمام دور صاحبه.
- **400 مع رسالة:** يستخدم الاستعلام شيئًا لا يدعمه الموجز، والرسالة تذكره.
