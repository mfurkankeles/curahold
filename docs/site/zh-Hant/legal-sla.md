# 服務水準協議（SLA）

> **草稿——須經律師核准。** 版本 2026-11-19.draft1。付費方案的服務條款一部分（不適用於試用）。[方括號] 內的數字為建議值：只承諾我們的監控能夠證明的數字。本文為英文版本的譯本，僅供閱讀便利；如有任何不一致，以英文版本為準。

## 1. 可用性

- **目標：**服務於每個日曆月的可用時間為 **[99.5]%**。
- **衡量方式：**每分鐘自至少兩個區域對登入頁面與 API 進行外部檢查；兩個區域皆失敗時，該分鐘計為不可用。數據顯示於狀態頁面 [狀態頁面網址]。
- **不計入：**至少提前 48 小時公告的計畫性維護（每月至多 [4] 小時，盡可能安排在伊斯坦堡時間 08:00–20:00 以外）；由客戶、其網路或其連接的第三方工具所造成的問題；依條款所為的停權；不可抗力；標示為 beta 的功能。

## 2. 服務抵免

| 每月可用性 | 抵免（占當月費用的比例） |
| --- | --- |
| 低於 [99.5]% | [10]% |
| 低於 [99.0]% | [25]% |
| 低於 [95.0]% | [50]% |

管理員須於該月結束後 30 天內透過支援管道申請抵免。抵免沖抵下一張發票，不以現金支付，且為可用性未達標的**唯一救濟**。如於任意六個月中有三個月可用性低於 [99.0]%，客戶得終止協議並取回預付費用。

## 3. 支援

| 嚴重程度 | 範例 | 首次回應 |
| --- | --- | --- |
| 1 — 緊急 | 服務中斷或資料面臨風險 | [4] 個上班小時 |
| 2 — 重大 | 主要功能失效，且無替代方案 | [1] 個工作天 |
| 3 — 輕微 | 功能失效，但有替代方案 | [2] 個工作天 |
| 4 — 詢問 | 操作方式、需求 | [3] 個工作天 |

上班時間：[伊斯坦堡時間週一至週五 09:00–18:00，土耳其國定假日除外]。管道：應用程式內說明與 [支援電子郵件]。

## 4. 備份與復原

- 至少每日備份，保存 35 天。
- **復原點目標（RPO）：**[24] 小時。**復原時間目標（RTO）：**[8] 小時。
- 至少每季進行還原測試 [待依代管設定確認]。

## 5. 變更

本服務水準協議依條款第 19 條所述方式變更；於付費訂閱期間內，任何變更皆不得降低目標。
