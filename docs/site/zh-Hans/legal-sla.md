# 服务等级协议（SLA）

> **草稿——须经律师批准。** 版本 2026-11-19.draft1。付费方案的服务条款组成部分（不适用于试用）。[方括号] 内的数字为建议值：只承诺我们的监控能够证明的数字。本文是英文文本的译本，仅为方便阅读；如有任何不一致，以英文文本为准。

## 1. 可用性

- **目标：**服务在每个日历月的可用时间为 **[99.5]%**。
- **衡量方式：**每分钟从至少两个区域对登录页面和 API 进行外部检查；两个区域均失败时，该分钟计为不可用。数据显示在状态页面 [状态页面地址]。
- **不计入：**至少提前 48 小时公告的计划维护（每月最多 [4] 小时，尽可能安排在伊斯坦布尔时间 08:00–20:00 以外）；由客户、其网络或其连接的第三方工具造成的问题；依据条款实施的暂停；不可抗力；标为 beta 的功能。

## 2. 服务抵扣

| 月度可用性 | 抵扣（占当月费用的比例） |
| --- | --- |
| 低于 [99.5]% | [10]% |
| 低于 [99.0]% | [25]% |
| 低于 [95.0]% | [50]% |

管理员须在月份结束后 30 天内通过支持渠道申请抵扣。抵扣冲抵下一张发票，不以现金支付，是可用性未达标的**唯一救济**。如在任意六个月中有三个月可用性低于 [99.0]%，客户可终止协议并获退还预付费用。

## 3. 支持

| 严重程度 | 示例 | 首次响应 |
| --- | --- | --- |
| 1 — 紧急 | 服务中断或数据面临风险 | [4] 个工作小时 |
| 2 — 重大 | 关键功能失效，无替代方案 | [1] 个工作日 |
| 3 — 轻微 | 功能失效，有替代方案 | [2] 个工作日 |
| 4 — 咨询 | 使用方法、需求 | [3] 个工作日 |

工作时间：[伊斯坦布尔时间周一至周五 09:00–18:00，土耳其法定节假日除外]。渠道：应用内帮助和 [支持邮箱]。

## 4. 备份与恢复

- 至少每天备份，保存 35 天。
- **恢复点目标（RPO）：**[24] 小时。**恢复时间目标（RTO）：**[8] 小时。
- 至少每季度进行恢复测试 [待依据托管配置确认]。

## 5. 变更

本服务等级协议按条款第 19 条所述方式变更；在付费订阅期内，任何变更均不得降低目标。
