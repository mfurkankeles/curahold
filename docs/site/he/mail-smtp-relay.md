# דוא״ל המוצר דרך Google Workspace ‏(ממסר SMTP)

> למנהלים ולמפעילים. השלימו קודם את מדריך ה-DNS: הממסר מוסר היטב רק כש-SPF, ‏DKIM ו-DMARC עוברים.

‏Curahold שולחת קישורי כניסה, תזכורות, הודעות על תקופת ניסיון וסיכומים. תיבת Gmail רגילה אינה מיועדת לדואר של אפליקציה; **שירות ממסר ה-SMTP** של Google כן. הוא נשאר בתוך Google Workspace, בלי שירות דואר נוסף.

## 1. הפעלת הממסר

מסוף הניהול → אפליקציות → Google Workspace → ‏Gmail → **ניתוב** → **שירות ממסר SMTP** → הגדרה:

- **שולחים מורשים:** רק כתובות בדומיינים שלי.
- **אימות:** סמנו **דרישת אימות SMTP** (השירות המתארח רץ על שרתים בלי כתובת קבועה, ולכן מתחבר במקום להיכלל ברשימת היתר). באירוח עצמי עם כתובת קבועה אפשר לבחור "קבלת דואר רק מכתובות IP מסוימות".
- **הצפנה:** סמנו **דרישת הצפנת TLS**.
- שמרו. ההפעלה עשויה להימשך עד שעה.

## 2. חשבון השליחה

בחרו את המשתמש שיתחבר לממסר (חשבון הבעלים מספיק) עם אימות דו-שלבי, וצרו עבורו **סיסמה לאפליקציה**. הוסיפו את `no-reply@` ככינוי שלו.

## 3. הגדרת Curahold

**מתארח (Cloudflare Workers)** — כסודות (`wrangler secret put …`):

| הגדרה | ערך |
| --- | --- |
| `SMTP_RELAY_USER` | המשתמש משלב 2, למשל `owner@example.com` |
| `SMTP_RELAY_PASSWORD` | הסיסמה לאפליקציה שלו |
| `EMAIL_FROM` | `Curahold <no-reply@example.com>` |
| `EMAIL_PROVIDER` | `google_relay` (נבחר אוטומטית כששני הקודמים מוגדרים) |
| `SMTP_RELAY_HOST`, `SMTP_RELAY_PORT` | רק כדי לשנות את ברירות המחדל `smtp-relay.gmail.com` ו-`587` |

נתיב הקוד: `api/src/lib/smtpRelay.ts` ‏(STARTTLS בפורט 587; פורט 25 סגור ב-Workers).

**אירוח עצמי** — בקובץ `.env`:

```
SMTP_URL=smtp://owner%40example.com:APP-PASSWORD@smtp-relay.gmail.com:587
EMAIL_FROM=Curahold <no-reply@example.com>
```

הפעילו את האפליקציה מחדש.

## 4. בדיקה

צאו מהחשבון ובקשו קישור כניסה. ההודעה צריכה להגיע מ-`no-reply@…`, עם SPF, ‏DKIM ו-DMARC במצב **PASS**. אם לא הגיע דבר, יומן האפליקציה מציין באיזה שלב SMTP היה הכישלון.

## 5. מגבלות — ומתי נדרש שירות שליחה ייעודי

הממסר מקבל עד **10,000 נמענים ביום לכל משתמש** (המגבלה שפרסמה Google; בדקו). העברת דואר המוצר לשירות שליחה ייעודי — החלטה של הבעלים, ובתשלום — נדרשת כשקורה **אחד** מאלה:

- דואר המוצר היומי עובר בקביעות את **מחצית המגבלה** (5,000 נמענים ביום);
- המסירה נפגעת: החזרות מעל **2%**, תלונות קרוב ל-**0.1%**, או הודעות שנוחתות בספאם;
- נדרשים אירועי מסירה לכל הודעה (webhooks) או מוניטין שליחה נפרד לסוגי דואר שונים;
- מתוכננים **קמפיינים שיווקיים** — לעולם לא דרך הממסר.

המעבר הוא הגדרה: לשירות המתארח כבר יש מנהל התקן לשירות ייעודי (`EMAIL_PROVIDER=resend` עם `RESEND_API_KEY`). הוסיפו אותו לדף מעבדי המשנה והודיעו למנהלים 30 יום מראש.

## 6. כשדואר לא יוצא {#failures}

דחייה זמנית (`421`, `450`, `451` או חיבור שנפל) מנוסה פעם נוספת בחיבור חדש. דחייה קבועה לא: `535` (סיסמת האפליקציה שונתה או בוטלה: צרו חדשה והחליפו את `SMTP_RELAY_PASSWORD`), `550 5.4.5` (המגבלה היומית), `550 5.1.1` (כתובת שלא קיימת). אנשים רואים אז "לא הצלחנו לשלוח את הדוא״ל כרגע. נסו שוב בעוד כמה דקות; אם זה חוזר, פנו למנהל המערכת." בשפה שלהם, ולעולם לא את תשובת השרת; היא נכתבת ביומן השגיאות של האפליקציה יחד עם שלב ה-SMTP.
