# 보안과 개인정보

## 회사끼리는 서로 볼 수 없습니다

모든 쿼리는 데이터베이스의 행 수준 보안 규칙 아래에서 실행됩니다. 한 회사의 데이터는 다른 회사의 주소, API, 커넥터로 어떤 방법으로도 읽을 수 없습니다. 역할과 필드 규칙도 같은 계층에서 강제됩니다.

## 세션과 기기

세션은 기기에 묶여 있어서, 복사한 쿠키는 다른 컴퓨터에서 동작하지 않습니다. 기기 수 제한을 넘기면 가장 오래된 세션이 로그아웃됩니다. 내 설정 → 기기에서 세션을 보고 끝낼 수 있습니다.

## 패스키와 2단계 인증

이메일 링크 외에 **패스키**(지문, 얼굴, 기기 PIN)로 로그인할 수 있고, **2단계 인증**을 더할 수 있습니다: 인증 앱과, 휴대폰을 잃어버렸을 때 쓸 일회용 복구 코드 10개. **내 기기 → 로그인 보안**에서 설정하며, 여기서 다른 모든 기기를 한 번에 로그아웃할 수도 있습니다. 관리자는 **설정 → 로그인**에서 관리자 또는 모든 사람에게 2단계 인증을 요구할 수 있고, 로그인할 때마다 서버에서 확인합니다. 싱글 사인온으로 로그인하는 사람에게는 다시 묻지 않습니다. ID 공급자가 처리하기 때문입니다. 아무도 갇히지 않습니다. 관리자가 누군가의 2단계 인증을 재설정할 수 있고, 자체 호스팅 설치는 서버 환경에 재설정 항목(`RESET_SECOND_STEP`)이 있습니다.

역할 변경, 싱글 사인온이나 SCIM 변경, API 키 만들기, 개인 데이터 내보내기·삭제, 사람 제거, 활동 로그 내보내기는 로그인한 지 10분이 넘었다면 본인 확인(패스키, 앱 코드, 이메일 코드)을 요청합니다.

## 기기에 보관되는 것

연결 없이도 읽을 수 있도록, 앱은 마지막으로 본 목록의 사본을 브라우저 자체 저장소에 보관합니다(작업, 보드, 고객, 받은 편지함. 첨부 파일과 설정은 제외). 사본은 그 기기와 그 브라우저에만 남고 어디로도 보내지 않습니다. 로그아웃하거나, 서버에서 세션이 끝난 뒤 처음 연결될 때 지워집니다. 공용 컴퓨터에서는 다 쓴 뒤 로그아웃하세요.

## 활동 로그

로그인, 2단계 확인, 사람과 역할 변경, 연결, API 키, webhook, 개인정보 작업은 활동 기록(설정 → 활동 기록)에 남습니다. 기록은 절대 바뀌지 않고, 앱이 쓰는 데이터베이스 역할로도 지울 수 없습니다. 12개월이 지나면 야간 정리 작업이 지웁니다(데이터베이스는 90일보다 최근 기록의 삭제를 거부합니다). **기록 내보내기**는 연속된 SHA-256 지문과 함께 내려받으며, 마지막 지문도 기록에 남아 나중에 사본을 확인할 수 있습니다.

## 고객 포털

고객 포털은 자체 세션과 쿠키를 가진 별도 도메인에서 동작합니다. 포털 요청 뒤의 데이터베이스 역할은 어떤 테이블에도 권한이 없으며, 로그인한 사람의 회사에 공유된 데이터만 돌려주는 함수만 호출할 수 있습니다. 자세한 내용: [고객 포털](/docs/ko/customer-portal/).

## Curahold 지원팀의 접근

Curahold 지원팀은 사람의 동의가 있을 때만 회사에 들어옵니다: 도움 요청에서 체크 상자를 선택하고 기간(24시간~7일)을 고르면 됩니다. 지원팀은 그 사람이 보는 것을 보며 보기만 할 수 있고, 아무것도 바꿀 수 없습니다. 접근은 고른 기간이 끝나면 종료되고, 언제든 닫을 수 있습니다. 모든 방문과 그동안 지원팀이 읽은 내용은 지원 담당자 이름과 함께 활동 로그에 기록됩니다. 관리자는 **설정 → 보안 → 지원 접근**에서 관리자로 제한하거나 끌 수 있습니다. 자세한 내용: [도움 받기](/docs/ko/getting-help/).

## 개인 데이터

설정 → 사람에서 사람의 메뉴에 다음이 있습니다.

- **개인 데이터 다운로드:** 그 사람에 관한 모든 것을 파일 하나로.
- **개인 데이터 삭제:** 이름과 이메일이 지워지고, 그 사람이 한 업무는 익명으로 남습니다. 먼저 그 사람의 고객과 열린 작업을 다른 사람에게 넘기세요.
- **삭제**하면 그 사람이 CuraAI에 한 질문, 알림, 채팅 연결, 패스키와 2단계 확인, 세션 녹화, AI 팀 메모에 있는 그 사람의 주소나 전체 이름도 지워집니다. 법에 따라 남는 것: 청구서, 회사를 대신해 약관에 동의한 기록, 주소 없이 지문만 남긴 동의 기록.
- **고객사의 사람들**(설정 → 고객 포털 → 로그인할 수 있는 사람): 개인정보를 관리하는 관리자는 **데이터 내려받기** 또는 **개인정보 삭제**를 할 수 있습니다. 삭제하면 포털 계정 자체가 지워지고, 작성한 내용은 이름 없이 남습니다.

### 회사 전체 삭제

관리자는 **설정 → 회사 → 회사 삭제**에서 회사 주소를 입력해 요청할 수 있습니다. 30일 동안은 아무것도 지워지지 않습니다. 회사는 평소처럼 운영되고, 내보내기도 할 수 있으며, 어느 관리자든 취소할 수 있습니다. 그 뒤 파일과 연결 키를 포함한 모든 것이 영구 삭제되고, 무엇을 지웠는지 적은 삭제 증명서(이름이나 주소 없음)가 남습니다. 청구서는 세법에 따라 보관됩니다. 백업은 호스팅 업체의 일정에 따라 순차적으로 지워집니다.

### 개인정보 관련 요청

**설정 → 회사 → 개인정보 관련 요청**에서 개인정보 권한이 있는 사람은 개인이 자신의 데이터에 대해 요청한 내용을 적용 법률과 함께 모두 기록합니다. 열람, 정정, 삭제, 처리 제한, 이의 제기, 개인정보 이동, 동의 철회가 대상입니다. 기한은 해당 법에 따라 계산되며(예: KVKK와 GDPR은 30일, 한국 개인정보 보호법(PIPA)은 10일), 기한이 지난 요청은 빨간색과 아이콘으로 표시됩니다. 처리가 끝나면 답변 완료 또는 거절로 표시하세요. 모든 변경은 활동 기록에 남습니다. 실제 처리는 해당 사람의 내보내기와 삭제 기능으로 합니다.

## 보관 기간

| 데이터 | 보관 기간 |
| --- | --- |
| 알림 | 90일 |
| 끝난 세션 | 90일 |
| 동기화 기록 | 90일 |
| [휴지통](/docs/ko/trash/)에 있는 삭제된 고객, 레코드, 작업 등 | 30일 후 파일과 함께 삭제. 관리자는 더 일찍 삭제 가능 |
| 가져오기 실행 취소 데이터 | 30일 |
| 웹훅 전송 기록 | 7일 |
| 오류 기록(무엇이 어디서 깨졌는지. 요청 내용은 절대 없음) | 30일 |
| 폐기한 API 키 | 30일 |
| 활동 기록 | 12개월 |
| 도움 요청과 그 메시지·파일 | 마지막 변경 후 24개월 |
| CuraAI에 한 질문 | 회사가 정한 기간(변경하지 않았다면 30일) |
| 삭제된 회사 | 요청 30일 뒤 삭제 |

## 저장된 비밀 정보

CRM과 채팅 연결의 인증 정보, 웹훅 서명 비밀 키는 암호화해 저장합니다. API 키는 다이제스트만 보관하며, 키 자체는 한 번만 보여 주고 다시는 볼 수 없습니다.
