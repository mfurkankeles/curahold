# Google Workspace（SMTP リレー）で製品メールを送る

> 管理者・運用担当者向け。先に DNS のガイドを済ませてください。SPF、DKIM、DMARC が通っていないとリレーは正しく届けられません。

Curahold はログインリンク、リマインダー、トライアルのお知らせ、サマリーを送ります。通常の Gmail のメールボックスはアプリケーションの送信用ではありません。Google の **SMTP リレーサービス**はそのためのもので、Google Workspace の中で完結し、別のメールサービスは不要です。

## 1. リレーを有効にする

管理コンソール → アプリ → Google Workspace → Gmail → **ルーティング** → **SMTP リレーサービス** → 設定：

- **許可する送信者：**自分のドメインのアドレスのみ。
- **認証：** **SMTP 認証を必須にする**をオン（ホスト型は固定アドレスのないサーバーで動くため、許可リストではなくログインで認証します）。固定アドレスのセルフホストでは「指定した IP アドレスからのメールのみ受け入れる」も選べます。
- **暗号化：** **TLS 暗号化を必須にする**をオン。
- 保存します。反映まで最大 1 時間かかります。

## 2. 送信用アカウント

リレーにログインするユーザー（オーナーで十分）を決め、2 段階認証プロセスをオンにして**アプリ パスワード**を作成します。`no-reply@` をそのユーザーのエイリアスにします。

## 3. Curahold に設定する

**ホスト型（Cloudflare Workers）**— シークレットとして設定（`wrangler secret put …`）：

| 設定 | 値 |
| --- | --- |
| `SMTP_RELAY_USER` | 手順 2 のユーザー（例：`owner@example.com`） |
| `SMTP_RELAY_PASSWORD` | そのアプリ パスワード |
| `EMAIL_FROM` | `Curahold <no-reply@example.com>` |
| `EMAIL_PROVIDER` | `google_relay`（上の 2 つがあれば自動で選ばれます） |
| `SMTP_RELAY_HOST`、`SMTP_RELAY_PORT` | 既定値 `smtp-relay.gmail.com`、`587` を変える場合のみ |

コードは `api/src/lib/smtpRelay.ts` です（587 番ポートで STARTTLS。Workers では 25 番ポートは使えません）。

**セルフホスト**— `.env` ファイルに：

```
SMTP_URL=smtp://owner%40example.com:APP-PASSWORD@smtp-relay.gmail.com:587
EMAIL_FROM=Curahold <no-reply@example.com>
```

アプリを再起動します。

## 4. 確認

ログアウトしてログインリンクを依頼します。メールが `no-reply@…` から届き、SPF、DKIM、DMARC が **PASS** であることを確認します。届かない場合は、アプリのログに失敗した SMTP の段階が記録されます。

## 5. 上限と、専用の配信サービスが必要になる時期

リレーはユーザーあたり **1 日 10,000 件の宛先**まで受け付けます（Google の公表値。確認してください）。次の**いずれか**に当てはまったら、製品メールを専用の配信サービスに移します（オーナーの判断で、有料です）。

- 製品メールが日常的に上限の**半分**（1 日 5,000 件）を超える。
- 到達率が下がる：バウンスが **2%** 超、苦情が **0.1%** に近づく、迷惑メールに入る。
- メールごとの配信イベント（webhook）や、種類ごとに分けた送信レピュテーションが必要になる。
- **マーケティングキャンペーン**を予定している（リレーからは決して送らない）。

切り替えは設定だけです。ホスト型には専用サービス用のドライバーがあります（`EMAIL_PROVIDER=resend` と `RESEND_API_KEY`）。先に再委託先ページに追加し、管理者に 30 日前に通知してください。
